# Milestone 12 真实截图测试集与质量评估

本文档用于执行并记录 Milestone 12：真实中文平台截图测试集与识别质量评估。

当前状态：测试记录框架已建立，真实截图执行待补充。

阻塞项：仓库内当前没有可用于测试的 20 张真实中文平台截图，因此不得填写虚假的成功率、失败率或样例结果。待用户提供截图后，按本文档逐项执行并补全记录。

当前执行策略：先由用户输入 3 到 5 张真实截图，沉淀可用于面试展示的端到端样例；确认上传、识别、查询、分析和 Markdown 输出闭环稳定后，再扩展到完整 20 张质量评估集。成本估算和同图多模型比较不作为本轮真实测试的前置条件。

## 目标

- 第一阶段使用 3 到 5 张真实截图准备面试演示样例。
- 使用至少 20 张中文平台截图验证当前异步采集链路。
- 覆盖成功、失败、空结果和模型误识别样例。
- 验证 `raw_content` 和 `context_target` 是否严格来自截图可见文字。
- 验证 tags 是否为现象性标签，且数据库中不带 `#`。
- 验证 OSS 证据链、MySQL 入库、RabbitMQ Consumer、Markdown 输出和页面轮询是否形成闭环。

## 测试范围

本轮测试覆盖当前完整链路：

```text
截图上传
-> SHA-256 image_hash
-> Bloom Filter / MySQL 去重
-> OSS 私有 Bucket 上传
-> capture_record PROCESSING 任务记录
-> RabbitMQ 投递
-> Consumer 后台识别
-> MySQL 更新多条 corpus_record
-> Markdown 输出
-> Thymeleaf 页面轮询展示最终结果
```

## 测试前提

- MySQL 已创建数据库并执行 `src/main/resources/db/schema.sql`。
- RabbitMQ 正常运行，`localhost:5672` 和 `localhost:15672` 可访问。
- OSS 私有 Bucket 配置正确，可上传、下载和生成 signed URL。
- 已配置至少一个可用多模态 Provider：Gemini 或 OpenRouter。
- 应用已启动，`/corpus/upload` 页面可访问。
- 已准备至少 20 张真实中文平台截图。

## 执行步骤

1. 启动 RabbitMQ、MySQL、应用服务。
2. 打开 `http://localhost:8080/corpus/upload`。
3. 逐张上传截图，默认 `force=false`。
4. 记录上传后返回的 `captureRecordId`、`captureId`、`imageHash`、初始 `parseStatus`。
5. 等待页面轮询从 `PROCESSING` 变为最终状态。
6. 调用 `GET /api/v1/corpus/captures/{captureId}` 复核所有记录。
7. 检查 Markdown 文件是否生成，且不包含 signed URL。
8. 对每条识别结果人工核对截图可见文字。
9. 在测试记录表中填写结果。
10. 对失败或误识别样例补充原因分析和后续改进建议。

## API 辅助命令

上传截图：

```bash
curl -X POST "http://localhost:8080/api/v1/corpus/upload" \
  -F "file=@sample.png" \
  -F "force=false"
```

按采集批次查询：

```bash
curl "http://localhost:8080/api/v1/corpus/captures/{captureId}"
```

获取 signed URL：

```bash
curl "http://localhost:8080/api/v1/corpus/{id}/image-url"
```

## 质量验收口径

| 维度 | 通过标准 | 不通过示例 |
| --- | --- | --- |
| `raw_content` 忠实度 | 评论原文来自截图可见文字，未总结、未补全、未改写 | 模型把多条评论合并、补充截图外信息、改写语气 |
| `context_target` 忠实度 | 上下文来自截图可见文字，可为空 | 推测帖子主题、生成摘要、补全不可见内容 |
| 评论拆分 | 一条可见评论对应一条 `corpus_record` | 多条评论合并为一条，或把昵称/按钮当评论 |
| tags 合规性 | 经验性、现象性标签，数据库不带 `#` | 心理诊断、人身判断、政治立场判断、带 `#` 入库 |
| 状态流转 | `PROCESSING` 最终变为 `SUCCESS` / `EMPTY_RESULT` / `MODEL_FAILED` / `PARSE_FAILED` | 长时间停留 `PROCESSING` 且无错误信息 |
| Markdown 输出 | `SUCCESS` 记录生成 Markdown，且不保存 signed URL | Markdown 缺失、路径错误、写入 signed URL |
| 证据链 | `image_hash`、`oss_object_key`、`captureId` 可追溯 | 数据库缺少 OSS key 或 hash |
| 去重 | 重复图 `force=false` 返回历史结果 | 重复图再次调用模型并生成重复语料 |
